# Healthy — موقع متجر ألبان (واجهة أمامية كاملة)

متجر إلكتروني لمتجر **Healthy** في العريش: تصفح المنتجات، سلة، وإرسال الطلب عبر **واتساب**، والدفع نقدًا عند الاستلام.
المشروع HTML5 + CSS3 + Bootstrap 5.3 (RTL) + JavaScript بدون أي مكتبات ثقيلة أو Backend.

> **مهم:** كل المنتجات والأسعار ورقم واتساب ورسوم التوصيل **بيانات تجريبية** إلى أن تُستبدل. طالما `demoMode: true` يظهر شريط أصفر يوضح ذلك للزوار.

## 1. التشغيل

لا يحتاج أي تثبيت. الطريقة الأسهل:

```bash
cd healthy-store
python3 -m http.server 8000      # ثم افتح http://localhost:8000
```

أو افتح `index.html` مباشرة في المتصفح (يعمل، لكن يفضّل خادم محلي لاختبار الخطوط والأداء).

## 2. هيكل المشروع

```
index.html  products.html  cart.html  about.html  contact.html
assets/
  images/{logo,products,categories,banners}   assets/icons/favicon.svg
  vendor/   Bootstrap 5.3 RTL + Bootstrap Icons + خط Tajawal (مستضافة محليًا، لا اعتماد على CDN)
css/   style.css (التوكنز والأساسيات)  components.css (المكونات)  responsive.css (الشاشات الأكبر)
js/    config.js  products.js  cart.js  checkout.js  filters.js  main.js
```

| الملف | وظيفته |
|---|---|
| `js/config.js` | **كل** بيانات المتجر: رقم واتساب، رسوم التوصيل، العنوان، المواعيد، نص الشريط العلوي |
| `js/products.js` | الأقسام والمنتجات (الاسم، السعر، الصورة، المتاح، العروض) |
| `js/cart.js` | السلة (LocalStorage) والحسابات |
| `js/checkout.js` | صفحة السلة، التحقق من النموذج، رسالة واتساب |
| `js/filters.js` | بحث وفلاتر وترتيب صفحة المنتجات (الحالة في رابط الصفحة) |

## 3. إضافة رقم واتساب الحقيقي

افتح `js/config.js` وغيّر **سطرًا واحدًا**:

```js
whatsappNumber: "201012345678",   // 20 + رقم الموبايل بدون الصفر الأول، أرقام فقط بدون + أو مسافات
```

كل أزرار واتساب ورابط الطلب تقرأ من هذا السطر. إذا بقي الرقم `20XXXXXXXXXX` فلن يُفتح واتساب، وستظهر رسالة الطلب في الصفحة ليتم نسخها (وضع التجربة).

## 4. تغيير بيانات المتجر

في `js/config.js`:
- `deliveryFee` رسوم التوصيل (الحالية 20 جنيه **تجريبية**) — `freeDeliveryMinimum` لحد التوصيل المجاني (`null` = لا يوجد).
- `address`, `addressDetail`, `workingHours` العنوان والمواعيد — `mapsUrl` رابط خرائط جوجل (يظهر الزر والخريطة عند إضافته).
- `announcement` نص الشريط العلوي — `social` روابط السوشيال (الأيقونات تصبح روابط عند إضافتها).
- `demoMode: false` لإخفاء شريط «نسخة تجريبية» بعد إدخال البيانات الحقيقية.

## 5. تغيير المنتجات والأسعار والصور

في `js/products.js` عدّل المصفوفة `PRODUCTS`. كل منتج:

```js
{ id: 1, name: "حليب Healthy طبيعي", category: "milk", description: "حليب طبيعي...",
  price: 45, oldPrice: null, size: "1 لتر", image: "assets/images/products/milk-1.svg",
  available: true, featured: true, onSale: false }
```

- **العروض:** ضع `onSale: true` و`oldPrice` أعلى من `price`. تظهر نسبة الخصم تلقائيًا، وقسم العروض **يختفي كليًا** إذا لم يوجد عرض فعّال (وكذلك رابط «العروض»).
- **الأكثر طلبًا:** `featured: true` (يظهر أول 8 منتجات في الرئيسية).
- **غير متوفر:** `available: false` (لا يمكن إضافته للسلة).
- **الأقسام:** مصفوفة `CATEGORIES` (القيم المسموحة لـ `category`: `milk` `cheese` `yogurt` `juice`).
- **الصور:** ضع الصورة في `assets/images/products/` وغيّر المسار. الصور الحالية رسومات توضيحية (SVG) مؤقتة بألوان الهوية؛ استبدلها بصور حقيقية بصيغة **WebP** مربعة (800×800 مناسب) وبخلفية شفافة أو بيضاء. خلفية البطاقة ملوّنة حسب القسم (`--tint-*` في `css/style.css`).

## 6. تغيير الشعار

الشعار الحالي **بديل مؤقت** (شتلة خضراء/صفراء + كلمة Healthy) لأن صورة المتجر لم تُرفق بعد. استبدل الملفات بنفس الأسماء:
`assets/images/logo/logo.svg` (الترويسة) و`logo-white.svg` (الفوتر) و`assets/icons/favicon.svg`.
نسبة العرض إلى الارتفاع التقريبية 4:1. بعد تغيير الشعار حدّث ألوان `:root` في `css/style.css` إذا لزم.

## 7. النشر

الموقع ملفات ثابتة، ارفع المجلد كما هو إلى أي استضافة ثابتة:
- **Netlify / Vercel / Cloudflare Pages:** اسحب المجلد أو اربط المستودع، بدون أمر build، والمجلد الجذر هو `healthy-store`.
- **GitHub Pages:** ارفع الملفات وفعّل Pages من الفرع الرئيسي.
- **استضافة عادية (cPanel):** ارفع المحتوى إلى `public_html`.

بعد النشر: ضع الرابط الكامل في `og:image` داخل كل ملف HTML (مثل `https://your-domain.com/assets/images/banners/og-image.png`)، واستبدل الصورة بصورة حقيقية للمتجر عند توفرها، واجعل `demoMode: false`.

## 8. كيف تعمل رحلة الطلب

1. العميل يضيف منتجات (زر «أضف للسلة» يتحول إلى عدّاد كمية). السلة تُحفظ في LocalStorage ولا تضيع عند التحديث.
2. صفحة السلة: مراجعة، تعديل الكميات، اختيار توصيل أو استلام من الفرع، إدخال الاسم والموبايل (يقبل الأرقام العربية و+20) والعنوان.
3. «إرسال الطلب عبر واتساب» يتحقق من البيانات، يبني الرسالة العربية من السلة الفعلية، ويفتح `wa.me` في تبويب جديد.
4. تظهر شاشة توضح أن الطلب **غير مؤكد** حتى يرد المتجر. تبقى السلة كما هي حتى يختار العميل «أرسلت الطلب، ابدأ طلبًا جديدًا» أو يفرغها.

## 9. ملاحظات تقنية

- المنتجات مولّدة بـ JavaScript من `products.js` (بدون خادم). إن أردت فهرسة كل منتج في محركات البحث لاحقًا فستحتاج صفحات منتجات مولّدة مسبقًا أو Backend.
- ألوان الهوية كما في المواصفات، مع تعديل واحد للقراءة: النص الثانوي `#5E676C` (بدل `#737B80`) ليحقق تباينًا مقروءًا، ويستخدم `#737B80` للأسعار القديمة فقط. النص فوق الأخضر داكن لنفس السبب.
- بطاقات المنتجات: عمودان على الموبايل، 3 على التابلت، 4 على الديسكتوب.
- عدّل رقم الحد الأقصى لكمية المنتج الواحد من `maxQtyPerItem` (الافتراضي 20).
